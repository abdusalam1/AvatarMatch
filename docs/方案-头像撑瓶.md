# 头像撑瓶 · 玩法设计

> 目标：把「观众的互动」变成「瓶子里的体积」，一眼看懂、越热闹越好看、每 15–20 秒有一次高潮。

## 1. 一句话与名场面

**一句话**：同一个观众的头像掉进瓶子，同尺寸相撞就合成更大的，合到把瓶子撑爆。

**名场面（最重要的 3 秒）**：
- 榜一大哥连送三个火箭，瓶底长出一个占半个瓶子的巨物；
- 瓶压 95%，裂纹爬满玻璃，全场刷「快炸了」；
- 撑破瞬间：玻璃淡出、碎屑四散、大字「撑破！」+ 语音念出撑破者的名字，1.35 秒后新瓶开张。

## 2. 互动 → 掉落（经济系统）

| 事件 | 掉落 | 说明 |
|---|---|---|
| 进场 `join` | 1 | 首次进场播报欢迎 |
| 点赞 `like` | 每 5 个 1 个 | 余数累计；单次 `count` 最多算 999 |
| 评论 `comment` | 2 | 弹幕进滚动播报，不朗读 |
| 关注/分享 `follow/share` | 3 | |
| 礼物 `gift` | 3 / 6 / 12 + 一个 2–3 级 | 见下表 |
| 连击 | +1/次，最多 +5 | 同一 uid 3 秒内连续互动；点赞、进场不叠 |

礼物分档（按名字关键词，认不出就按上游的 `gift` 类别兜底）：

| 档位 | 例子 | 掉落 | 直接送 |
|---|---|---|---|
| 小 | 小心心、棒棒糖、荧光棒 | 3 | 2 级 |
| 中 | 玫瑰、啤酒、奶茶 | 6 | 2 级 |
| 大 | 火箭、嘉年华、跑车、城堡 | 12 | 3 级 |

另有统一倍率 `giftBoost`（默认 1.0）和单个礼物 `count` 上限 ×3，防止一个"礼物雨"直接刷爆。

**为什么点赞是 5 个一掉**：抖音点赞是洪水（单人一次几十上百），若每赞必掉，瓶口 2 秒就堵死。
5 个一掉既能体现"点赞也有用"，又不会让点赞淹没评论/礼物的存在感。

## 3. 合成

- 条件：**同一个 uid** + **同一 tier** + 接触（圆心距 ≤ r1+r2+1.6）。
- 结果：tier+1，半径 × `mergeScale`（默认 1.26），位置取中点，速度取平均并轻微上抛。
- 面积变化：1.26² = 1.59 < 2，所以**每次合成会释放 20% 面积** → 合成是"泄压"，不是"加速爆炸"。
- 等级上限 12；tier 12 半径约 310（≈ 瓶半径），实际到不了就炸了。
- 不同观众、不同尺寸的头像只会互相挤开，不会合——保证"认脸"。

## 4. 物理

- 世界固定 1200×1000，重力 1700 单位/秒²，弹性 0.2，切向摩擦 0.25；子步长 1/120，最多 5 步/帧。
- 瓶身是**高度场**：每层 y 有一个允许半宽 `W(y)`。
  - 直瓶颈：`W = 52`（y < 240）；
  - 斜肩：`W` 从 52 线性到 183（y 240 → 360，终点正好落在瓶壁上）；
  - 圆瓶：`W = √(R² − (y−cy)²)`。
- 碰撞判定：头像在**圆瓶内**（到圆心距离 + r ≤ R）或在**漏斗内**（|dx| + r ≤ W(y)）都算合法；
  否则按更小的穿透量沿半径/坡面法线推回并反弹。
- 早先的坑：用"圆 SDF ∪ 瓶颈矩形"会在肩膀形成两个凹角，头像卡在肩上永远掉不下来；
  改成高度场后没有接缝，肩部自动滑落。
- 瓶口两条车道轮流放行（x = cx ± (neckHalf − r − 6)），单车道吞吐不够；
  放行前检查瓶口 90 单位内有没有堵住。

## 5. 瓶压与撑破

```
fill     = Σ π r²  (瓶内所有头像)
capacity = π R² × burstFill      // burstFill 默认 0.82
fillP    = fill / capacity

crowded  = 瓶内头像数 ≥ maxPieces × 0.5
jamP     = crowded ? clamp((queue.length − 100) / 180, 0, 1) : 0

pressure = max(fillP, jamP)
```

- `pressure ≥ 1` → 撑破；单个头像半径 ≥ 0.94R 也算撑破（巨物顶穿瓶壁）。
- **排队不算早期压力**：瓶子还空着时排再长也只是"没来得及掉"，不能一刷屏就在空瓶上炸。
- 撑破者 = **头像总面积最大**的观众（并列看最大单块）。
- 结算：`lastBurst = {bottleNo, reason, breaker, pieces, pressure, at}`，写进撑破榜；1.35 秒后新瓶。
- 瓶压里程碑 50% / 80% / 95% 各播报一次，给观众"要来了"的预期。

## 6. 节奏与数值

- 演示模式 4.5–5 次互动/秒 ≈ 8–16 次掉落/秒；瓶口上限 12/秒。
- 实测（60 秒演示）：约 **18–22 秒一瓶**，平均排队 50–70，最大等级 5–6。
- 一局的"看头"分布：0–5 秒撒小头像，5–15 秒合成出中大物，15–20 秒瓶压告警 + 撑破。
- 礼物是"加速器"不是"胜负手"：免费互动也能合出大物，送礼只是更快、更炫。

## 7. 防刷 / 防滚雪球

| 风险 | 手段 |
|---|---|
| 单人连点刷屏 | 点赞按 5 个累计；队列上限 320；瓶口吞吐 12/秒 |
| 单人无限滚雪球 | 合成面积损耗 20%；瓶内上限 150；撑破后整瓶清空 |
| 大礼物直接赢 | 礼物只给 3/6/12 个 + 一个 2–3 级，不给更高等级 |
| 空瓶被刷爆 | 排队压力只在瓶内半满后生效 |
| 画面太乱 | 「清空瓶子」按钮；现场可调重力/阈值/上限 |

## 8. 播报（视觉 + 语音）

- 视觉：Canvas 左侧 toast、底部滚动播报、右侧撑破榜、顶部瓶压条。
- 语音：进场欢迎、合成 4 级以上、大礼物（3 级）、瓶压 80%、撑破、换瓶；
  队列上限 6，同类限流（欢迎 2.5s、瓶压 12s），绝不逐条念弹幕。
- 合规：只做"更快更炫"，不做抽奖/盲盒/倍率/随机奖励；画面常驻「虚拟场景 · AI 生成画面」。

## 9. 已知取舍

1. **瓶子"看起来"没满就炸**：瓶压按面积算，几个大物就能把面积顶到 82%，视觉上高度可能只有一半。
   好处是节奏快，坏处是"撑满"的直觉弱一点；可以调低 `mergeScale` 或调高 `burstFill` 来让画面更满。
2. **排队不可见**：Queue 只在左侧数据面板显示数字，画布上不画。避免"口子堵住"时出现一列悬空头像。
3. **只做横屏**：16:9 适合直播伴侣/OBS 采集；竖屏需要另一套 HUD，本版本没做。
